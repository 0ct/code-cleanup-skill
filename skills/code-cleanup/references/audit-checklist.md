# 十类问题审计手册

每一类给出：**判定证据标准** → **检索手段** → **常见误判** → **可自动修的条件**。

通用前提：

- `repo_scan.py` 的命中只是线索。凡是要删要改的，必须有本文件所说的"证据标准"，否则一律进待确认清单。
- 检索顺序：**语言自带工具（见 `tooling.md`）> 脚本命中 > grep**。工具有模块图，grep 没有；但工具看不懂动态入口，脚本和 grep 能补。
- 第 9、10 类是 agent 时代的产物，详细判定见 `agent-residue.md`。

---

## 1. 损坏与不可达代码

**定义**：写了但永远执行不到，或引用已经不存在的目标。

| 形态 | 判定证据 |
| --- | --- |
| 指向已删文件的 import | 相对路径解析不到文件；构建/类型检查报 module not found |
| 永久为假的分支 | 条件是字面量、`false`/`0`/`null`、恒等比较，或依赖已被删除的常量 |
| `return`/`raise`/`throw` 之后的语句 | 同一 block 内不可达 |
| 被同名定义遮蔽 | 两次定义同名函数/变量，后一个覆盖前一个，前一个无任何可达调用 |
| 死循环后代码 / 永不 resolve 的 await 之后分支 | 静态可判 |
| 注册后无人匹配的路由或 handler | 路由表里有，客户端与测试都不请求；且无对外承诺（公开 API 例外，降 R2） |

**检索**：

```bash
# 相对引用是否可解析
python3 scripts/repo_scan.py <repo>            # broken_import 段
# 导出后是否有引用
rg -n "export (const|function|class|default)" src | ...
rg -n "\bSymbolName\b" --glob '!<定义文件>'    # 引用计数必须为 0 且无动态入口
# 明显不可达
rg -n -U "(return|raise|throw)[^\n]*\n\s+(?!\}|else|except|catch|finally|elif)\S"
```

**常见误判**：

- 动态加载绕开静态引用：`importlib`、`require(variable)`、字符串路由、插件目录扫描、Django/Flask 装饰器注册、`conftest.py` 自动收集、Next.js 文件路由、`__init__.py` 的 `*` 导出。
- 供外部消费的导出：库的 `__all__`、`index.ts` barrel、类型声明文件、`package.json` 的 `exports` 字段——项目内没人用是对的。
- 测试专用钩子：只在测试里被调用，但测试没进同一引用图。
- 平台/条件编译：`#ifdef`、`process.platform`、构建期常量替换。

**可自动修的条件**：不可达可由语言语义静态证明（非猜测）；被删符号**不是**任何导出面的一部分；文件不在公共入口链上。

## 2. 前后矛盾的逻辑

**定义**：同一事实在两处有不同说法，且至少一处是错的。这是最值钱也最容易漏的一类。

| 形态 | 判定证据 |
| --- | --- |
| 常量/枚举重复定义且取值不同 | 两处定义同一语义，值或成员集合不一致 |
| 校验规则不一致 | 同一字段在 DTO 层与 DB 层/前端层规则不同（长度、正则、必填） |
| 注释描述的算法与实现不符 | 注释说"按时间倒序"，代码是正序；注释参数名与签名不符 |
| 默认值相反 | 配置默认开着，文档说默认关 |
| 同名函数两份实现 | 逻辑不同，调用点分散在两边 |
| 前后端契约漂移 | 类型定义、字段名、错误码集合不一致 |
| 状态机缺边 | 有 `pending → done`，但没有失败态处理，或某状态无法退出 |

**检索**：

```bash
# 同一常量名多处定义
rg -n "^(export )?(const|let|var|final|constexpr)\s+[A-Z][A-Z0-9_]+" | awk -F: '{print $3}' | sort | uniq -d
# 注释中的参数名 vs 函数签名（人工读）
rg -n -B2 "^\s*(def|function|func|fn|public .*\()" 
# 同一字段的多处校验
rg -n "validate|schema|z\.|pydantic|joi|yup|@Valid" 
```

**常见误判**：刻意的分层差异（前端宽松、后端严格）是设计，不是矛盾——判据是有没有一处文档/类型声明承诺两者一致。

**可自动修的条件**：几乎不存在。矛盾意味着要选一个"对的"，这需要知道意图 → **默认全部进 R2 清单**，只报告不修。唯一例外：注释与实现不符且实现有其他证据支持（测试、调用方断言）→ R1，订正注释。

## 3. 重复、过时、被取代的实现

**定义**：同一逻辑存在多份，或旧实现留在原地没有删。

**判定证据**：

- 结构相同、命名带 `old`/`legacy`/`v1`/`_deprecated`/`old_`/`Backup`
- 两个实现只有细微差异（一个多打了日志，一个少了一个参数）
- 新实现已被广泛调用，旧实现只剩零散或零调用
- 复制粘贴痕迹：注释里还留着原模块名、变量名与上下文不匹配

**检索**：

```bash
python3 scripts/repo_scan.py <repo>          # dup_file / dup_block 段
rg -n "old|legacy|deprecated|v1|v2|backup|unused|tmp" --type-add 'code:*.{py,ts,js,go,rs}' -tcode
# 同名不同路径
rg --files | xargs -n1 basename | sort | uniq -d
```

**常见误判**：为兼容旧客户端保留的旧接口（有版本协商或 deprecation 声明）；A/B 两套实现都活着；测试 fixture 与生产实现长得像但职责不同。

**可自动修的条件**：重复的两份中，一份引用计数为 0 且无外部承诺（无版本协商、无 deprecated 声明、不在导出面）→ R1 删旧留新。**两份都在用 → 合并属于重构，禁止，进清单。**

## 4. 未使用的代码

**定义**：存在但没有任何消费者。

| 形态 | 判定证据 |
| --- | --- |
| 未使用 import | 语言级可判（编译器/类型检查直接报） |
| 只写不读的变量/字段 | 赋值后从未被读取；DB 字段无查询方 |
| 无人调用的私有函数 | 引用计数 0，且非反射/装饰器注册目标 |
| 传了没人用的参数 | 调用方传值，函数体不读 |
| 未使用的配置项 | `.env.example`/yaml 有键，代码无读取 |
| 未使用的路由/中间件/注册项 | 注册表有，无请求路径 |
| 未使用的 CSS/资源/字体 | 无引用（构建产物除外） |

**检索**：

```bash
rg -n "^\s*(import|from)\s" <file>        # 与文件内实际使用的标识符比对
rg -c "\bname\b"                          # 全仓引用计数
python3 scripts/repo_scan.py <repo>       # unused_file / deps_unused / env_drift
```

**常见误判**：`__all__` 导出、类型声明、框架约定（`setup`/`teardown`/`get_queryset`）、装饰器副作用、`conftest.py`、副作用 import（注册 polyfill）、序列化字段（只被框架反射读）。

**可自动修的条件**：语言级可判的未使用 import / 局部变量 → R1。任何跨文件"没人调用"的判断 → 必须先排除动态入口，否则 R2。

## 5. 低效写法

**定义**：能跑但代价明显高于必要，或违反所用 API 的成本模型。

| 形态 | 判据 |
| --- | --- |
| 循环内 I/O 或查询 | N+1；循环里 `await`/网络/文件读取 |
| 重复构建同构对象 | 循环内编译正则、建连接、建 client、建 logger |
| 全量加载 | `read()` 整个文件/表后只取一行；无分页 |
| 重复计算 | 循环不变量提到循环外即可 |
| 阻塞热路径 | 同步文件/网络调用在请求处理函数里 |
| 无谓拷贝 | 大数组多次 `map`+`filter` 链、深拷贝只读数据 |

**检索**：先定位热路径（请求处理、定时任务、批处理入口），再在热路径内找 `for`/`while` 里的 I/O 与构造调用。**不要全仓搜索然后批量"优化"。**

**常见误判**：缓存/连接池已经在外层；数据量有上界；可读性优先的写法；微基准证明差异可忽略。

**可自动修的条件**：**默认不允许**。低效修复必然改变执行顺序或副作用时序，属于重构。只有在能证明"纯函数体内、无副作用、结果完全等价"时才降到 R1（例如把循环内不变的正则编译提到模块级——但仍需确认线程安全与编译成本）。

## 6. 过期的注释、配置、测试

**定义**：描述的是已经不存在的行为。

**判定证据**：

- 注释里的参数名/返回类型/字段名与当前签名不符
- 注释说"临时方案，后续替换"，替换已完成
- 配置项在代码里无消费方，或在 `config.schema` 里不存在
- 测试断言的是已删除的行为、引用已删除的 fixture、mock 的接口签名与实现不符
- 测试名描述的意图与被测代码无关
- CI 配置里跑的是已重命名的脚本

**检索**：

```bash
python3 scripts/repo_scan.py <repo>       # markers / deps_unused / version_drift / test_gap
rg -n "TODO|FIXME|HACK|deprecated|临时|暂时|后续|先这样" --type-add ...
# 配置键是否有消费方
rg -n "configKeyName"
```

**常见误判**：注释承载"为什么"（历史决策、外部约束），不是"是什么"——这类注释即使提到旧实现也应保留。测试里的 TODO 可能是待修 bug，删了会丢信息。

**可自动修的条件**：

- 参数名/类型不符的注释 → R1 订正
- 已失效的临时开关、无消费方的配置项 → 先 R2（可能有外部部署依赖），确认后删
- 过期测试 → **不自动删**。测试是行为契约，删测试必须有替代覆盖，否则 R2 并标注"覆盖缺口"

## 7. 临时残留

**定义**：调试期或工具期产物，不应进仓库。

| 形态 | 判据 |
| --- | --- |
| 备份/副本文件 | `*.bak` `*.orig` `*.old` `*~` `*.backup.*` `copy` 命名、`新建文本文档` |
| 系统/编辑器垃圾 | `.DS_Store` `Thumbs.db` `.idea/` `.vscode/`（后两者若已被 git 跟踪则需判断是否团队共享） |
| 调试输出 | 库代码里的 `console.log`/`print`/`fmt.Print`/`pprint`/`debugger`/`breakpoint()` |
| 调试用死代码 | 被注释掉的一整段实现、`// console.log(x)` |
| 硬编码本地环境 | `/Users/<name>/…`、`localhost:3000`、测试邮箱、假 token、临时 URL |
| 临时绕过 | 注释掉的校验、`// @ts-ignore` 盖住的真错误、被禁用的 lint 规则 |
| 提交残留 | conflict marker（`<<<<<<<`）、`--no-verify` 跳过后的坏提交 |

**检索**：

```bash
python3 scripts/repo_scan.py <repo>       # junk / markers / commented_code / hardcoded
rg -n "^(<<<<<<<|=======|>>>>>>>)"
rg -n "console\.log|debugger|breakpoint\(\)|pdb\.set_trace|binding\.pry" -g '!**/test*'
```

**常见误判**：CLI/脚本目录里的 `print` 就是输出；结构化日志的 `logger.debug` 不是残留；`@ts-ignore` 可能是绕第三方类型 bug 的唯一办法；示例代码里的 `localhost` 是对的；**规则文档/正则定义/告警文案里"提到"某个模式，不等于该模式真的出现**——自匹配是这类检测最常见的噪音来源。

**可自动修的条件**：备份文件、系统垃圾、库代码内无争议的调试输出、已确认无引用的注释代码 → R0/R1。**疑似凭据永远不自动改**，只报告并要求人工轮换。

## 8. 依赖

**定义**：声明与使用不一致，或依赖集合本身有冗余。

| 形态 | 判据 |
| --- | --- |
| 声明未使用 | 依赖在清单里，全仓无 import/无配置引用/无脚本调用 |
| 使用未声明 | 代码 import 了，清单里没有（靠环境预装） |
| 同一库多版本 | lock 文件里同一包多个版本；monorepo 各包版本冲突 |
| 重型依赖换一行工具函数 | 为 `lodash.get` 引入整个 lodash |
| 版本区间过宽 | `*`/`latest`，或与 lock 不一致导致不可复现 |
| 已废弃包 | npm/PyPI 标记 deprecated、无维护 |

**检索**：

```bash
python3 scripts/repo_scan.py <repo>       # deps_unused / deps_undeclared
npm ls --all 2>/dev/null | grep -E "deduped|UNMET"
pip list --format=freeze | ...
```

**常见误判**（这一类误报率最高）：

- 只通过 CLI 用的：`pytest`、`black`、`ruff`、`eslint`、`prettier`、`ts-node`、`nodemon`、`husky`、`uvicorn`、`gunicorn`
- 隐式加载：`PyMySQL`（供 SQLAlchemy dialect）、`psycopg2`、`@types/*`、`core-js`、`reflect-metadata`、`tslib`
- 构建/插件机制：`postcss`、`autoprefixer`、`tailwindcss`、`babel` 预设、Vite 插件
- 运行时由部署环境提供：`aws-lambda` 类型包、平台 SDK

**可自动修的条件**：**从不自动删依赖。** 删依赖必须同时改清单 + lock 文件 + 验证安装与运行，属于 R2。报告时给出三件事：包名、唯一可能的用途、验证命令。

## 9. 无谓抽象与过度防御

**定义**：为"稳妥"或"将来"而加的间接层与兜底，代价是真实行为被掩盖。

| 形态 | 判定证据 |
| --- | --- |
| 只转发的包装 | 函数体只有一行 `return impl(...)`；只被调用一次；无单独测试 |
| 单实现的接口 | 接口/协议只有一个实现，参数完全一致；注释说"为将来扩展" |
| 薄壳分层 | `XxxManager`/`XxxService`/`XxxHelper` 实质无逻辑 |
| 空异常处理 | `except: pass`、`catch {}`、`catch { return null }` |
| 默认值兜底掩盖失败 | 失败时返回与正常值无法区分的默认值 |
| 重复校验 | 同一输入在 2-3 层重复校验，规则完全相同 |
| 为纯函数包重试/超时 | 无 I/O 的函数被重试、被超时包裹 |
| 预留参数 | 可选参数全仓无调用方传入 |

**检索**：

```bash
# 单行转发（各语言通用形态）
rg -n "return\s+\w+\((\w+(,\s*)?)*\)\s*;?\s*$" -g '*.{py,ts,js,go,rs}'
# 空异常块
rg -n -U "except[^\n]*:\s*\n\s*pass|catch\s*\([^)]*\)\s*\{\s*\}"
# 只出现一次的定义 + 一次调用
knip --include classMembers,exports   # 或 vulture --min-confidence 90
```

**常见误判**：薄壳是有意的接缝（测试替身、DI 注入点、跨模块边界）——判据是**有没有测试在这个接缝上替换实现**；兜底是产品要求的降级策略（读 README 与 issue 判断，不要凭直觉）。

**可自动修的条件**：**没有。** 这一类的删除都会改变调用链或错误路径，全部 R2 起步；触到鉴权/支付/数据写入的按 R3。只报告，附"为什么它可能存在"的猜测让人确认。

## 10. 指令与文档漂移

**定义**：描述仓库的文本（指令文件、文档、注释、配置、示例）与代码现状不符。这是最容易被跳过、但危害最长的一类。

| 形态 | 判定证据 |
| --- | --- |
| 指令文件指向已删模块 | `AGENTS.md`/`CLAUDE.md`/`README` 里的路径 `test -f` 不存在 |
| 文档命令跑不通 | 文档里的脚本/flag 在 `package.json scripts` 或 CLI 帮助里不存在 |
| 示例 import 失效 | 文档代码块里的 import 路径解析不到 |
| 注释引用已删文件 | "见 `xxx.py`"，文件已删 |
| 方案描述与实现相反 | 文档说用 X，代码是 Y（且不是过渡期） |
| CI 跑旧脚本 | workflow 里的路径/命令已重命名 |
| 状态文件过期 | `STATE.md`/`TODO.md`/设计文档描述的目标已实现或已放弃 |

**检索**：

```bash
# 文档里出现的路径是否存在
rg -o "[\w./-]+\.(py|ts|tsx|js|go|rs|sh)" AGENTS.md README.md docs/ | sort -u
# 文档里的命令是否存在
rg -n "npm run |make |uv run |go run |cargo " README.md AGENTS.md
# CI 里的脚本路径
rg -n "run:|script:" .github/workflows/ 2>/dev/null
```

**常见误判**：注释解释"为什么"（历史决策、外部约束）——即使提到旧实现也应保留；废弃声明（deprecation notice）本身就是正确内容；计划文档描述未完成的目标不等于漂移。

**可自动修的条件**：**没有。** 修改指令与文档会改变后续所有 agent 的行为，全部 R2，且必须在报告中单独成组、点名"哪些描述因哪次删除而失效"。

## 交叉检查（容易漏的四件事）

1. **删了 A 之后，B 是否变成死代码？** 清理有级联效应，删完一轮要再扫一遍。
2. **改完之后，注释/文档/测试是否又过期了？** 第二轮扫描专门看这个。
3. **有没有描述被删代码的文本还留着？** 这是"僵尸模式"的种子——下一个 agent 会照它把代码写回来。
4. **`git diff` 里有没有"看起来顺手改的"？** 有就不是清理，是重构，拆出去。
